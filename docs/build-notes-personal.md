# Astra maintenance runbook

## Refreshing search filter params
InnerTube `search` uses protobuf `params` strings. If a filter stops narrowing
results, re-derive from ytmusicapi:

1. Open https://github.com/sigma67/ytmusicapi/blob/main/ytmusicapi/parsers/search.py
2. Read `get_search_params` + `_get_param2` (filters: songs=II, videos=IQ,
   albums=IY, artists=Ig, playlists=Io).
3. Update `kSearchFilterParams` in `lib/core/api_constants.dart`.

Bad params are non-fatal: the API ignores them and the app falls back to
parsing the unfiltered result set (classifying by browseId prefix).

## Stream resolver
Order: InnerTube iOS player → Piped → Invidious. Free public instances rotate;
extend `kPipedInstances` / `kInvidiousInstances` in api_constants.dart. Dead
instances are auto-blacklisted per session.

## Known parser notes
- `musicResponsiveHeaderRenderer` (new) vs `musicDetailHeaderRenderer`
  (legacy) are both handled for browse pages.
- Album track lists rely on `playlistItemData.videoId`; charts rely on
  `musicResponsiveListItemRenderer`.
- `musicCardShelfRenderer` = search "Top result" card.

## iOS background audio
`UIBackgroundModes: [audio]` must exist in ios/Runner/Info.plist (generated by
`flutter create`, patched by the CI workflow per run).
